# 后台驻留与应用退出

主窗口的关闭按钮和 Alt+F4 只隐藏窗口，不销毁 WebView、不终止 Pi Bridge 或当前会话。关闭时不显示退出确认。后台仍然接收会话事件，重新显示窗口时保留现有页面状态。

系统托盘使用应用图标。左键点击图标，或右键选择“显示主界面”，会显示、还原并激活原主窗口。右键菜单中的“退出应用”才会触发退出；启动失败界面已有的“退出应用”也使用同一条退出路径。

## 生命周期

- Rust `lifecycle` 模块管理托盘和窗口事件；Renderer 只通过 `ipc/system.ts` 的 `exitApp` 调用明确退出命令。
- 托盘使用固定 ID，创建前检查已有实例；初始化和窗口关闭事件在主事件线程执行，避免重复注册。
- 托盘初始化失败时保留主窗口，显示包含错误码的故障提示，并安装“显示主界面 / 退出应用”备用应用菜单。再次关闭会重试托盘创建，失败时仍不隐藏窗口。托盘与备用菜单均无法创建时中止启动，不启动 Bridge。
- 隐藏、显示、还原或激活失败会报告稳定错误；正常关闭不显示任何退出提示。还原过程中即使某一步失败，也尝试剩余操作。
- 未完成显式退出清理时拦截 `ExitRequested`。显式退出使用原子状态防止重复调度，在后台线程调用现有 `BridgeRuntime::shutdown`，等待 Bridge 协议关闭和现有超时终止机制完成，再退出 Tauri。最终 `Exit` 事件再次调用幂等清理作为兜底。
- 操作系统强制结束进程不属于可拦截的正常退出流程。

## 手动验收

1. 启动应用并运行一个较长会话，关闭主窗口，确认进程及托盘仍在且会话继续执行。
2. 左键点击托盘，确认显示原会话、消息持续更新；最小化后再次点击，确认窗口还原并激活。
3. 多次关闭、显示，确认始终只有一个托盘图标，右键“显示主界面”正常。
4. 会话运行时右键“退出应用”，确认应用、Bridge 及其子进程退出，托盘图标消失。
5. 启动失败界面点击“退出应用”，确认真正退出；正常窗口关闭不出现退出确认。
6. 在托盘不可用环境确认主窗口保持可见、错误提示明确，且备用应用菜单可以退出。

自动测试覆盖关闭前的托盘可用性检查、隐藏失败、恢复顺序与失败后的继续恢复、退出防重和清理完成前禁止退出。系统托盘的实际显示、操作系统焦点策略和进程回收需按以上步骤在桌面环境验收。

Rust 当前未配置覆盖率采集，本次不能确认新模块达到 80% 行覆盖率；原生托盘创建和菜单事件接线主要依赖桌面验收，存在平台集成风险。前端沿用现有 Vitest 覆盖率门禁。
