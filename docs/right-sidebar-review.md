# 右侧工作区面板与会话审查

日期：2026-09-27。本文补充 `pi-tauri-desktop-architecture-plan.md`，不改变
Renderer → Rust Core → Pi Bridge → 官方 Pi SDK 的依赖方向。

## 交互与参考范围

参考 `PI-Desktop` 的侧栏交互独立实现，未复制其 LGPL 源码。

- 内置审查、文件列表；动态打开文件和预览标签。移除内嵌浏览器、
  浏览器 IPC、原生子窗口命令和对应快捷键。普通链接的显式外部打开不受影响。
- 标签支持关闭、重新打开、中键关闭、拖拽排序、边缘自动滚动。
  `Alt+Left/Right` 调整顺序，方向键及 Home/End 导航，Delete/Backspace 关闭。
  加号固定在滚动条带之外，最后一个标签关闭后保留启动器。
- 首次打开显示工具选择列表，不自动打开审查或文件标签。选择工具后，面板开关、
  工具标签和审查范围保持，文件列表与 Git 审查自动读取当前工作区。
- 文件、预览和选中路径按工作区隔离；同工作区换会话不重置资源，会话审查使用
  当前会话 ID。标签顺序按工作区保存在 sessionStorage。关闭面板时保留已完成缓存
  并停用后台读取，关闭全部标签后返回选择列表。
- 拖动宽度以 animation frame 合并更新，释放后持久化；支持键盘调整与双击重置。
- 本应用 Files 是受授权工作区限制的原生目录视图，不迁入参考应用的
  `contributes.views` 插件宿主或浏览器生态。现有宽度偏好与宿主布局规则保留。

## 文件浏览与预览

`workspace_list_entries` 通过 Rust 校验工作区授权，逐目录按需加载，目录优先排序。
每页最多 200 项；游标基于类别和名称，单次枚举最多 100,000 个直接子项，
不递归扫描整个仓库。拒绝越界路径、`.git`、控制字符和符号链接/重解析点。
Windows 授权根、绝对文件路径和 canonicalize 结果使用统一路径表示后进行边界比较。
打开或恢复会话先完成工作区登记，再向侧栏发布路径；旧导航的迟到结果不能激活工作区。

目录缓存按工作区隔离。支持刷新、失败重试、分页、选中文件的祖先展开，
以及树控件上下/左右/Home/End 键盘导航。折叠或刷新移除焦点项后，焦点入口
回退到可见祖先或首项。

文本文件使用原有有界读取（512 KiB），源码每页 200 行并保留实际行号；
复制仍针对完整已读取内容。图片、Markdown 和文档走既有分类预览，文本/Markdown
快速预览最多渲染 5,000 行并显示提示；二进制内容不冒充源码。

## Git 审查与性能

保留未暂存/已暂存范围、暂存/取消暂存、还原/未跟踪删除确认、初始化、提交、
提交并推送、force-with-lease、创建分支、统一/拆分视图、换行、文字差异、
空白过滤、富文本高亮、折叠和复制 git apply 命令。

- 状态请求只读取文件列表；文件默认折叠，展开才请求 diff。
- diff 并发最多 4 个；切换工作区、范围、空白过滤、刷新或停用面板后丢弃旧结果。
- 隐藏再显示复用已完成状态和差异缓存。手动刷新及 Git 操作使缓存失效；
  操作跨隐藏/重开完成时仍刷新原工作区，不能影响其他工作区。
- 每页 200 个差异行/拆分行；拆分布局最多 400 个代码行节点。
  词级计算只针对可见行并限制输入工作量；超过 4,000 字符的行不做语法高亮。
- 未展开文件不预先计算全组增删总数，显示“展开文件查看差异”或已读取统计。
- 文件树提供手动刷新；会话工具变更使用事件失效。当前不新增全工作区
  文件系统 watcher，因此外部程序修改后可手动刷新。

## 会话审查与协议兼容

JSONL 协议仍为 v1，新增能力 `session-file-review` 和操作
`session.review.list`、`session.review.detail`、`session.review.rollback`，
以及 `session.reviewChanged` 事件。TypeScript/Rust 同步校验请求、响应、
规范 UUID、UTC 毫秒时间戳、允许状态、分页与长度限制。缺少能力时返回明确错误。

Bridge 在官方 `write` / `edit` 工具的调用及结果事件中捕获前后快照，
通过官方 `pi.appendEntry` 写入 `pi-desktop-file-review-v1` 原生 custom entry，
不向模型上下文注入文件快照。Session 创建/打开时显式从 sessionManager 的
当前分支恢复记录，不依赖 `session_start` 或额外绑定扩展。

- 内存保留最多 256 个审查记录、64 个待完成工具调用；列表每页最多 50 条。
- 每份快照最多 32 KiB，仅支持安全普通 UTF-8 文本文件。敏感文件、二进制、
  非法 UTF-8、越界路径、`.git`、符号链接和硬链接不创建可逆快照。
- 差异使用有界 LCS；超出 1,000,000 个矩阵单元时降级为粗粒度替换，
  以 `diffTruncated` 明确标记，前端显示简化/截断提示。
- 失败、重叠、被后续写入改变的记录不能直接回滚。回滚需二次确认，
  校验预期文件存在性、哈希与文件身份；正在生成或存在待完成写入时拒绝回滚。
- 回滚结果写回原生记录，重新打开会话后保留状态；UI 成功后刷新 Git 和文件内容。
  此检查不是文件系统事务，不承诺对任意外部进程的并发写入提供原子隔离。
- 256 条为活动内存上限，不裁剪官方追加式会话文件。升级前没有快照的历史
  工具调用不能追溯恢复；超出快照限制的文件继续使用 Git 工作区审查。

## 验证

回归覆盖协议错误与边界、会话创建/恢复/回滚、路径授权与链接拒绝、目录分页、
懒加载/缓存/竞态、长差异分页、关闭重开、键盘与拖拽交互。所有外部依赖使用
fixture 或 mock，不读取用户真实凭据或修改用户仓库来进行自动化验收。

运行 `pnpm test`、`pnpm check`、`pnpm build`。资源受限环境可设置
`VITEST_MAX_WORKERS=2` 限制测试并行数；此设置不改变应用并发或测试超时。
浏览器视觉验收使用本地 Tauri mock fixture；不替代真实桌面与官方 SDK 的端到端验证。
