# 对话工具权限

对话框的权限按钮控制 Pi SDK 的 `tool_call` 扩展钩子。Renderer 仅通过类型化 IPC 修改模式、接收请求和回复；实际授权由 Bridge 的隐藏扩展执行，未获授权的工具返回阻止结果。SDK 未注册该钩子时会话创建或重载失败，不静默放行。

## 模式与工具清单

| 模式 | 界面名称 | 自动允许 | 需要审批 |
| --- | --- | --- | --- |
| `accept-edits` | 默认权限 | 工作区内的内置读取、写入、编辑 | 命令、扩展工具、工作区外或无法安全确认的路径 |
| `ask` | 每次询问 | 工作区内的内置 `read`、`grep`、`find`、`ls` | 写入、编辑、命令及其他工具 |
| `auto` | 完全访问 | 所有已启用工具 | 无逐次审批 |

“每次询问”仍自动允许上述工作区读取。扩展覆盖内置工具名称时，不使用内置读写豁免。路径检查规范化实际路径，检查现有祖先节点，并对符号链接、工作区外路径以及写入硬链接保守地要求审批。

工具启用清单与审批模式互相独立；完全访问不会启用已禁用工具。旧版工具清单偏好（包括自定义清单或全部工具）不会迁移成完全访问。没有原生权限记录的会话使用 `accept-edits`。

## 协议 v1 的增量字段

- `SessionConfiguration.permissionMode` 返回已确认模式。
- `session.configure` 和 `prompt` 接受可选 `permissionMode`；不传时保留当前模式。模式变化在会话繁忙时返回 `SESSION_BUSY`。
- `permission.list { sessionId }` 返回该会话待处理请求，最多 64 项；用于切换会话或重连后的恢复。
- `permission.reply { sessionId, requestId, decision }` 接受 `deny`、`allow-once`、`allow-session`。重复、过期或其他会话的请求返回 `PERMISSION_REQUEST_EXPIRED`。
- `permission.requested` 事件数据为 `{ requestId, toolCallId, toolName, summary, expiresAt }`。摘要最多 4096 字符，只投影命令或路径元数据，不投影文件内容、编辑正文和任意工具参数；常见密钥赋值、敏感 CLI 参数及 URL 用户信息会脱敏。
- `permission.resolved` 事件数据为 `{ requestId, decision }`。所有事件仍使用协议 v1 的会话标识和单调递增 `seq`。
- Tauri 对应命令为 `agent_list_permission_requests` 与 `agent_reply_permission`。

旧客户端可忽略新事件及配置字段；新客户端读取缺失的模式时显示默认权限。旧运行时不支持审批操作时返回 `TOOL_PERMISSIONS_UNSUPPORTED`，不能将工具清单变化当作审批成功。

## 保存、取消与授权范围

模式通过 Pi 原生会话的 `pi-desktop-tool-permissions-v1` 自定义条目保存并按当前分支恢复。缺少保存能力或写入失败返回 `PERMISSION_SAVE_FAILED`，原模式、已有请求和授权保持不变，不执行失败的权限提升。

“仅此一次”只处理当前请求。“允许本会话”在内存中授权该会话的同名工具后续调用，包括其他参数及路径，不是仅授权当前命令。该授权不写入原生记录；更改模式、关闭会话或退出 Bridge 会清除它。停止任务取消所有待处理请求，但不撤销已给出的会话工具授权。

请求 120 秒未答复自动拒绝。停止任务、关闭会话和资源重载会拒绝待处理请求；停止后再次提交提示时恢复审批钩子。繁忙会话不能重载扩展。失效的异步路径检查不能在取消之后重新建立请求。

## 安全边界

这是 SDK 工具审批，不是操作系统沙箱。获准的命令或工具可访问网络和工作区外资源；完全访问同样受系统账号本身权限约束。路径检查不是抵抗并发文件系统修改的强隔离。用户安装的扩展和 SDK 属于受信任代码，其扩展初始化及绕过工具调用的直接操作不受 `tool_call` 钩子控制。

摘要是受限提示，不是完整参数审计；过长内容会截断，未知凭据格式无法保证自动识别。不要在提示或工具参数中放入密钥。批准工具前应结合工具名称、工作区和可见操作判断。
